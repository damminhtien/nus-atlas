Since we cannot control the size of data, we measure the
speed of an algorithm by the number of passes through the

SON Algorithm – Pass 1

Repeatedly read small chunks of the file into main memory
and run A-priori to find all frequent itemsets
•
Note: we are not sampling, but processing the entire file
in memory-sized chunks

An itemset becomes a candidate if it is found to be
frequent in any one or more chunks.
• Like in the random sampling method, we must adjust the
support threshold proportionally.


If our chunk is a fraction 𝒑𝒑of the entire file, our
support threshold should be reduced to 𝒑𝒑𝒑𝒑

Pigeonhole principle: If an itemset appears at least 𝒔𝒔
times in whole, then it must appear at least 𝒑𝒑𝒑𝒑times
in some chunk of data. No false negatives!

Theorem: No false negatives

• If there is an itemset S  that is frequent in full data, but not
frequent in the sample (false negative), then the negative
border contains at least one itemset that is frequent in the
whole (algorithm does not terminate)
Proof by contradiction:
• Suppose not.  i.e.
1. There is an itemset S  frequent in the full data but not
frequent in the sample, and
2. Nothing in the negative border is frequent in the full data
• Let T  be a smallest subset of S that is not frequent in the
sample (every subset of T is frequent in the sample)


T  is frequent in the whole (subset of frequent set S).

T  is in the negative border (contradiction)
